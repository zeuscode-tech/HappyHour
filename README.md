# HappyHour

> Свежая еда со скидкой вместо списания.

HappyHour — food-tech сервис для Бишкека, который помогает кафе, пекарням и небольшим ресторанам продавать оставшуюся свежую еду ближе к закрытию. Пользователь видит актуальные предложения рядом, сравнивает цену, остаток и время, строит маршрут и покупает на месте.

**Bishkek · Food Waste · SDG 12**

## Зачем нужен проект

У заведений ежедневно остаётся качественная готовая еда, которую приходится списывать. Одновременно студентам и молодёжи не всегда доступно питание вне дома. HappyHour соединяет эти две стороны в одном простом сценарии.

- заведению — меньше списаний и дополнительная выручка;
- пользователю — доступная свежая еда рядом;
- городу — меньше пищевых отходов;
- малому бизнесу — простой канал продаж без сложной интеграции.

## Основной сценарий

1. Заведение создаёт предложение, указывает блюдо, цену, скидку, количество и время окончания.
2. Предложение сразу появляется в мобильном приложении и на карте.
3. Пользователь сравнивает цену, расстояние, свежесть, остаток и доступное время.
4. Пользователь открывает карточку, строит маршрут и приходит в заведение.
5. Покупка происходит на месте, а сотрудник обновляет остаток.

В первой версии нет доставки, встроенной оплаты и обязательного бронирования.

## Целевая аудитория

Основная аудитория — студенты и молодёжь 16–30 лет в Бишкеке. При выборе предложения для них важны:

- цена и размер скидки;
- расстояние до заведения;
- свежесть продукта;
- фактическое наличие;
- время до закрытия предложения.

Вторая аудитория — локальные кафе, пекарни, кофейни и небольшие рестораны, которым нужен быстрый и недорогой способ сократить списания.

- docs — продуктовые решения, API и сценарии тестирования.

## Основные сущности данных

- profiles — пользователи и роли;
- venues — заведения и координаты;
- venue_members — сотрудники заведений;
- offers — предложения, цены, остатки и сроки;
- categories — категории еды;
- offer_categories — связь предложений и категорий;
- favorites — избранные предложения;
- stock_events — история изменения остатков;
- push_tokens — устройства для уведомлений;
- reports — жалобы и модерация.

## Безопасность и правила доступа

- Row Level Security во всех пользовательских таблицах;
- посетитель видит только активные и подтверждённые предложения;
- сотрудник меняет данные только своего заведения;
- администратор модерирует заведения и контент;
- секреты хранятся только в переменных окружения;
- чувствительные действия проходят через серверные функции;
- изображения проверяются по формату и размеру.

## Definition of Done для первой версии

- заведение создаёт предложение с фото, ценой, количеством и временем окончания;
- предложение появляется в ленте и на карте;
- пользователь видит расстояние, остаток и актуальность;
- маршрут открывается корректно;
- остаток обновляется без перезапуска приложения;
- предложение автоматически скрывается после распродажи или окончания времени;
- критические сценарии проверены на iOS, Android и в веб-панели.
